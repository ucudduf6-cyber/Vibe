# Worker Online — настройка реальных переписок

В архиве сохранён прежний Worker (`index.html`). Кнопка «Реальные чаты / Вход» открывает `live.html` — отдельный модуль регистрации, входа и реальных личных сообщений. Он не начнёт работать между телефонами без настройки облачной базы данных.

1. Создайте проект в Supabase (https://supabase.com), запомните Project URL и **publishable/anon key**. Никогда не публикуйте `service_role` или секретный ключ.
2. В Supabase → SQL Editor выполните содержимое `schema.sql`.
3. В Supabase → Authentication → Providers включите Email; для безопасности оставьте подтверждение почты включённым. В Authentication → URL Configuration укажите адрес GitHub Pages в Site URL и Redirect URLs.
4. В `config.js` вставьте Project URL и публичный anon/publishable key. Затем загрузите **содержимое** папки в корень репозитория GitHub Pages (включая `live.html`, `live.js`, `config.js`).
5. Откройте `live.html`, зарегистрируйте двух пользователей с разных устройств, подтвердите email (если включено), войдите и найдите друг друга по точному юзернейму. Сразу после регистрации без подтверждения почты может потребоваться повторный вход.

**Важно:** в этой версии работают реальные личные сообщения между устройствами, вход, сохранение сессий, выход, локальное переключение максимум трёх аккаунтов, блокировка на сервере. Для каждого аккаунта используется отдельное хранилище токенов; при выходе сессия удаляется из данного слота. Для переписки нужны интернет и доступность Supabase. Подписки realtime требуют включённой публикации таблицы; есть запасной опрос каждые 4 секунды.

**Push на закрытом iPhone ещё не реализован:** Service Worker принимает push, но нужен отдельный защищённый сервер отправки Web Push, VAPID-ключи и база push-подписок. Нельзя обещать уведомления после закрытия приложения только средствами GitHub Pages. На iPhone запрос разрешения возможен после установки PWA на экран «Домой» и по действию пользователя. iOS не разрешает автоматически показывать системный запрос сразу при запуске без пользовательского действия.

**Ограничения:** группы, каналы и настройки из старого интерфейса остаются локальным демо. Реальная синхронизация групп и каналов, серверная фильтрация уведомлений и защищённое восстановление доступа потребуют отдельной разработки. Не используйте демо-часть для конфиденциальной информации. Пароли обрабатываются Supabase Auth, не хранятся в localStorage как текст. Для усиления безопасности включите MFA, rate limits и защиту email в настройках Supabase.
